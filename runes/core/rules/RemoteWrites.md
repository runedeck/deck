Remote writes belong to the owner and the ceremony. You may push to a remote branch you created, after the prek pipeline passes, with `jj push` or the repository's guarded push command. Never push to any other branch, force-push, or rewrite published history. One exception: when the owner directs a small fix straight to the default branch of a named repository, follow the small-fix path in the VersionControl Authorization companion, which requires the full prek check set with `REQUIRE_GATES=1` first. Do not run `gh pr create`, `gh pr ready`, `gh pr merge`, `gh pr close`, `gh pr comment`, `gh pr review`, `gh pr edit`, `gh issue comment`, `gh issue close`, a remote branch deletion, or a review-thread resolution on your own initiative, and do not reach the same effect through the API or a web page. The app opens the draft, the owner's key readies and seals it, the controller invites reviews, and only the reviewer identity resolves threads. When such a write is the next step, list the exact commands and ask: "Do you want me to do this on your behalf?" A yes covers those commands one time. Run them only in the session the owner is talking to, never from a child agent, and report each result.

The session the owner is talking to may run `rune sign open`, `rune sign submit`, and `rune sign next`. Each stops at the owner's hardware key. A child agent never runs them.

Report instead. A status table goes in your reply to the owner, never onto a pull request. Name every pull request by its full `https://` URL and every artifact by its absolute path, so the owner can act on the report without asking.
