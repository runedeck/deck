# Glossary

Generated from `ontology/rune.ttl` by `rune spec glossary --write`. Do not edit this file. Change the ontology.
A specification sets a term in italics at first use and cites it as `*term* [TERM]` with
`[TERM]: https://runedeck.ai/ns#Term` at the end of the file.

- **Occam's razor**: Of two instructions that pass the same check, the shorter one wins. [OCCAMSRAZOR]
- **accountable**: On a record: who approves the decision, the A of RACI. [ACCOUNTABLE]
- **agent**: The document that defines a persona and its tools for a harness to run. The running process is a prov:SoftwareAgent. [AGENT]
- **aliases**: On every artifact: other names it is known by, an Obsidian default. [ALIASES]
- **analysis baseline**: The set of results one run of analysis tools produced on a set of artifacts, kept so a later run is compared against it. [ANALYSISBASELINE]
- **analysis result**: One condition an analysis tool reports in an artifact, with the rule it violates and the location. [ANALYSISRESULT]
- **analysis rule**: One criterion for correctness that an analysis tool verifies, a general one or a convention of this deck. [ANALYSISRULE]
- **analysis tool**: A program that examines artifacts to detect problems without executing them: a linter, a validator, a shape checker, or a check script. [ANALYSISTOOL]
- **architecture decision record**: A decision record for a software architecture decision in the shape Michael Nygard set out in 2011: context, decision, status, consequences. [ARCHITECTUREDECISIONRECORD]
- **archived**: On a proposal: the date the archive step accepted the change, which is the acceptance date of every record it produced. [ARCHIVED]
- **artifact**: Any file the system tracks: an instruction, a record, a specification, or a companion. [ARTIFACT]
- **assembly**: The activity that resolves one canonical rune, its companions, and its variants into one instance for each harness and model, and records provenance. [ASSEMBLY]
- **attestation**: A proof recorded as a run of a change's scenarios against one commit, with what the transcript shows for each, bound by the transcript digest. [ATTESTATION]
- **author**: On every artifact: who wrote it, by handle. [AUTHOR]
- **canon**: The harness-neutral entrypoint document of a rune: SKILL.md for a skill, the rule file for a rule. [CANON]
- **capability**: One specification: canonical under docs/specs/, or a delta inside a change. [CAPABILITY]
- **change**: One spec-driven change under docs/changes/, active or archived. [CHANGE]
- **change**: On a record: the change that produced it. [CHANGE-KEY]
- **companion**: A document beside a canon that the canon routes to: reference material, or the instructions and quirks of one harness, kept out of the canon so they are easy to review and to compile. [COMPANION]
- **consulted**: On a record: whose input was used, people and models as model-id@harness, MADR's consulted. [CONSULTED]
- **coverage**: The binding of each requirement to the analysis tool that enforces it, or its listing as a missed requirement. [COVERAGE]
- **created**: On every artifact: the date it was first written. [CREATED]
- **decision record**: A record of one decision: its context, the options considered, and the outcome. [DECISIONRECORD]
- **decisions**: On a proposal: the records the change produced, by title. [DECISIONRECORD-KEY]
- **delta specification**: A change-local specification that lists added, modified, removed, or renamed requirements, merged into the canonical specification at sync or archive. [DELTA]
- **description**: On every artifact: one sentence that says what it is for. [DESCRIPTION]
- **dispatcher answer**: The answer the hook dispatcher encodes for the harness after an event's hook executions: allow, deny, or stop the turn, with a reason. [DISPATCHERANSWER]
- **falsifiability**: A requirement states a check that can fail. A statement nothing can fail is not a requirement. [FALSIFIABILITY]
- **fixture**: An input a test runs against, with the result the test asserts for it. [FIXTURE]
- **harness**: A program that runs a model with tools and loads instructions from directories it owns. [HARNESS]
- **hook**: A script bound to harness events, run by the hook dispatcher. It is code. [HOOK]
- **hook dispatcher**: The program that takes one harness event, runs the hooks deployed for it in order, and encodes one answer for the harness. [HOOKDISPATCHER]
- **hook execution**: One execution of the hook dispatcher for one harness event, with every hook it ran or failed to start. [HOOKEXECUTION]
- **hook metrics**: Counted facts a hook returns with its result, as identifiers and integers, copied into the hook record. [HOOKMETRICS]
- **hook record**: One line the hook dispatcher writes per hook it ran: harness, event, hook, session, file, duration, exit status, the answer, and metrics. [HOOKRECORD]
- **idea**: The human-authored capture a change starts from: a drawing, a transcript, or a prompt in the owner's vault. [IDEA]
- **informed**: On a record: who is told the outcome, MADR's informed. [INFORMED]
- **instance**: One concrete realization of a kind, as the file assembly writes into a target for one harness is an instance of its rune. [INSTANCE]
- **instruction**: A Markdown file a harness loads to steer a model: a skill, a rule, an agent, or a routine. [INSTRUCTION]
- **lifecycle**: The path a change takes: an optional canvas, then the specification, the decision record, the implementation, the review, and the merge. [LIFECYCLE]
- **lifecycle stage**: One step of the lifecycle, in order: canvas, specification, decision, implementation, review, merge. [STAGE]
- **linter**: An analysis tool that matches rule patterns against a file, one file at a time, and reports style and convention violations. [LINTER]
- **markdown architecture decision record**: An architecture decision record in Markdown with the MADR template: decision drivers, considered options, their pros and cons, and the outcome. [MARKDOWNARCHITECTUREDECISIONRECORD]
- **missed requirement**: A requirement no analysis tool checks yet, listed in the coverage as such. [MISSEDREQUIREMENT]
- **model**: The language model a harness runs. [MODEL]
- **module**: One domain of a deck that keeps its instructions, its defaults, and its checks together behind a small interface, so it can be added, replaced, or removed without a change elsewhere. [MODULE]
- **name**: On a rune canon: its name, which the Agent Skills specification requires beside description. [NAME]
- **project**: On a record: the project it belongs to, a DOAP project such as the deck. [PROJECT]
- **projection**: A representation that drops information from its source. A search index stays uncommitted, and a snapshot of a source outside the repository is committed only with a provenance sidecar that names its upstream. [PROJECTION]
- **proof**: Evidence that a candidate commit shows the behavior a scenario states. [PROOF]
- **provenance**: The sealed statement of where an instance came from: its source and digest, the transforms applied, and the builder, kept in the sidecar as an in-toto statement. [PROVENANCE]
- **recorded**: The day the proof was recorded. [RECORDED]
- **related**: On every artifact: neighbor artifacts, by id and title. [RELATED]
- **render**: A committed representation that a command the repository carries produces from a plain-text source and that regenerates from it byte for byte. [RENDER]
- **representation**: One form an artifact's content takes. The plain-text representation is the authoritative one, and every other representation derives from it. [REPRESENTATION]
- **requirement**: One `### Requirement:` with MUST text, part of a capability. [REQUIREMENT]
- **responsible**: On a record: who does the work, the R of RACI, which MADR leaves out. [RESPONSIBLE]
- **routine**: An instruction installed on a harness account, which runs it on a schedule. [ROUTINE]
- **rule**: An always-on instruction artifact under a rules/ tree. [RULE]
- **rune**: An instruction that follows the rune template: one canon, optional sidecar, companions, and variants. A skill, a rule, or an agent is a rune when it does. [RUNE]
- **scenario**: One `#### Scenario:` with WHEN and THEN, part of a requirement. [SCENARIO]
- **scenes**: What the proof records about one scenario. [SCENE]
- **sidecar**: A file beside a rune that holds what the canon does not: harness metadata, or sealed provenance under .provenance/. A sidecar never repeats a canon field. [SIDECAR]
- **skill**: A procedure artifact with a SKILL.md canon. [SKILL]
- **status**: On a record or a proposal: its asserted lifecycle status. The frontmatter is the authority, and a shape only catches a disagreement with the file's location. [STATUS]
- **structure schema**: The per-directory structural contract, serialized as .mdschema, that validates the files beside it. [STRUCTURESCHEMA]
- **structured architecture decision record**: A markdown architecture decision record with YAML frontmatter for status, dates, RACI, and provenance: the runeADR format the deck's records under docs/decisions/ use. [STRUCTUREDARCHITECTUREDECISIONRECORD]
- **supersedes**: On a record: the older record it replaces, which then states status superseded. [SUPERSEDES]
- **tags**: On every artifact: the topics it belongs to, as Obsidian tags. [TAGS]
- **target**: A directory one harness loads instructions from, and the destination a deployment writes into. [TARGET]
- **template**: A file with placeholders that a renderer fills to produce another file. [TEMPLATE]
- **title**: On every artifact: its human name. A rune canon says `name` instead, because Agent Skills owns that frontmatter. [TITLE]
- **transcript**: The sha256 of proof.txt as the README states it. [TRANSCRIPT]
- **type**: On every artifact: its kind as the directory states it: skill, rule, agent, hook, routine, adr, or proof. A shape holds the list, so the key and the directory never disagree. [TYPE]
- **updated**: On every artifact: the date of its last change. [UPDATED]
- **upstream**: On every artifact: the sources it was adapted from, as links, with the origin first. [UPSTREAM]
- **validator**: An analysis tool that decides whether an artifact is valid against a grammar, a schema, or a set of shapes, and reports nothing about style. [VALIDATOR]
- **variant**: A first-class alternative of a rune for one harness, one model, or one user, resolved at assembly: user, then harness and model, then harness, then the base rune. [VARIANT]
- **verdict**: The bench's judgment of one artifact against its baseline, from the metrics the bench measured. [VERDICT]
